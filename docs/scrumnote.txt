SPRINT 1: ARCHITECTURE & SETUP
Duration: Week 1-2
Sprint Goal: Establish project foundation, database schema, and RBAC setup

Tasks Completed:
────────────────────────────────────────────────────────────────────────────
1. PROJECT INITIALIZATION
   - Created Flask application structure
   - Set up virtual environment with Python 3.8+
   - Configured Git repository for version control
   - Defined directory structure (database/, models/, static/, templates/)

2. DATABASE SCHEMA DESIGN
   - Designed relational schema with 4 tables
   - USERS table: user authentication and role management
   - TICKETS table: ticket lifecycle with AI predictions
   - TICKET_REPLIES table: conversation history (1:N relationship)
   - TICKET_SIMILAR_MATCHES table: historical similarity (idle in final version)
   - Implemented foreign key constraints for data integrity
   - Created schema.sql for automated initialization

3. ROLE-BASED ACCESS CONTROL (RBAC)
   - Implemented three user roles: customer, agent, admin
   - Created decorator functions: @customer_required, @agent_required, @admin_required
   - Implemented session management with Flask sessions
   - Added password hashing using Werkzeug PBKDF2
   - Created login_required decorator for authentication

4. BASIC ROUTE STRUCTURE
   - /register: User registration with validation
   - /login: User authentication with credential verification
   - /logout: Session cleanup and redirect
   - Role-based dashboard routing (index() function)

5. CONFIGURATION MANAGEMENT
   - Created config.py for centralized configuration
   - Set SECRET_KEY for session security
   - Configured database path and schema path
   - Added environment variable support for production deployment

6. FRONTEND TEMPLATES
   - Created base.html with Jinja2 template inheritance
   - Implemented sidebar navigation structure
   - Created login.html and register.html forms
   - Added CSRF protection using Flask-WTF

Challenges:
────────────────────────────────────────────────────────────────────────────
- Understanding Flask session management best practices
- Designing optimal database schema for ticket lifecycle
- Implementing secure password hashing
- Configuring CSRF protection correctly

Solutions:
────────────────────────────────────────────────────────────────────────────
- Researched Flask documentation for session management
- Referenced SQLite foreign key documentation
- Used Werkzeug built-in password hashing functions
- Followed Flask-WTF documentation for CSRF token integration

Sprint Review:
────────────────────────────────────────────────────────────────────────────
✅ Database schema designed and implemented
✅ RBAC system working with three roles
✅ Authentication flow functional (register, login, logout)
✅ Basic template structure in place
✅ Configuration management centralized

Retrospective:
────────────────────────────────────────────────────────────────────────────
What went well: Clean architecture from the start, good documentation practices
What could improve: More test coverage for database operations
Action items: Add unit tests for authentication decorators


SPRINT 2: AI/ML ENGINE
Duration: Week 3-4
Sprint Goal: Implement TF-IDF vectorization and train classification models

Tasks Completed:
────────────────────────────────────────────────────────────────────────────
1. DATASET PREPARATION
   - Collected customer support ticket dataset
   - Preprocessed text data (lowercasing, stopword removal, lemmatization)
   - Balanced dataset across 4 categories (Technical, Billing, Account, General)
   - Labeled priority data (Critical, High, Medium, Low)

2. TF-IDF FEATURE EXTRACTION
   - Implemented TfidfVectorizer from scikit-learn
   - Configured max_features=5000 for efficiency
   - Used ngram_range=(1,2) for unigrams and bigrams
   - Removed English stopwords using NLTK
   - Applied lemmatization for text normalization

3. CATEGORY CLASSIFICATION MODEL
   - Trained Logistic Regression classifier for ticket categories
   - Used multi-class classification with One-vs-Rest strategy
   - Implemented probability estimation using predict_proba()
   - Evaluated model with accuracy and classification report
   - Serialized model using joblib for fast loading

4. PRIORITY CLASSIFICATION MODEL
   - Trained Logistic Regression classifier for ticket priority
   - Used similar pipeline as category model
   - Implemented confidence scoring for low-confidence flagging
   - Evaluated model performance with cross-validation
   - Serialized model using joblib

5. MODEL ARTIFACT MANAGEMENT
   - Created models/ directory for serialized artifacts
   - Saved 3 model files: tfidf_vectorizer.joblib, category_model.joblib, priority_model.joblib
   - Implemented model loading logic in ai_engine.py
   - Added safe fallback mechanism using rule-based heuristics

6. HEURISTIC FALLBACK SYSTEM
   - Implemented keyword-based fallback for missing models
   - Added technical keywords: error, crash, bug, fail, sync, 502, 404
   - Added billing keywords: charge, refund, invoice, payment, card
   - Added account keywords: login, password, 2fa, reset, profile
   - Default fallback: General Inquiry, Medium priority

Challenges:
────────────────────────────────────────────────────────────────────────────
- Balancing dataset across categories
- Tuning TF-IDF parameters for optimal performance
- Understanding Logistic Regression probability estimation
- Implementing safe fallback mechanism

Solutions:
────────────────────────────────────────────────────────────────────────────
- Used pandas for data manipulation and balancing
- Experimented with different max_features values
- Referenced scikit-learn documentation for predict_proba()
- Implemented rule-based fallback with keyword matching

Sprint Review:
────────────────────────────────────────────────────────────────────────────
✅ TF-IDF vectorizer trained and serialized
✅ Category classifier trained (Technical, Billing, Account, General)
✅ Priority classifier trained (Critical, High, Medium, Low)
✅ AI inference module (ai_engine.py) implemented
✅ Safe fallback mechanism working
✅ Model artifacts ready for production use

Retrospective:
────────────────────────────────────────────────────────────────────────────
What went well: Clean ML pipeline, good model performance
What could improve: More hyperparameter tuning, larger dataset
Action items: Consider advanced models (Random Forest, SVM) for future iterations

LESSONS LEARNED
────────────────────────────────────────────────────────────────────────────
1. Start with clean architecture to avoid refactoring later
2. Keep ML pipeline simple and explainable for academic projects
3. Use standard, well-documented libraries (Flask, scikit-learn)
4. Optimize for viva presentation, not enterprise complexity
5. Document everything with student-defensible comments
6. Test early and often to catch integration issues
7. Simplify navigation and UI for easier demo flow
8. Use safe fallbacks for ML models to ensure reliability
