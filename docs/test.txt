STEP 1: AUTO-APPROVED AUTHENTICATION
================================================================================

OBJECTIVE:
Verify that customer registration is auto-approved, login works with session
creation, and logout clears the session with confirmation modal.

PRECONDITIONS:
- Application running: python app.py
- Database initialized: compassiq.db exists
- No pre-existing user with test email

TEST PROCEDURE:

1.1 REGISTRATION TEST
---------------------
Action:
- Navigate to http://localhost:5000/register
- Fill registration form:
  * Full Name: "Test Customer"
  * Email: "test@compassiq.com"
  * Password: "Password@123"
  * Confirm Password: "Password@123"
  * Bill No / Product ID: "PROD-TEST-001"
- Click "Register" button

Expected Result:
- User redirected to /login page
- Success message: "Registration successful! Please login."
- Database verification:
  ```sql
  SELECT email, account_status FROM users WHERE email = 'test@compassiq.com';
  ```
  Expected: email='test@compassiq.com', account_status='APPROVED'

Edge Case Check:
- If registration fails due to duplicate email:
  * Error message: "Email already registered"
  * Verify account_status is 'APPROVED' (not 'PENDING')

Verification Criteria:
✓ Registration form accepts valid input
✓ Account created with APPROVED status (no admin approval needed)
✓ Redirect to login page after successful registration
✓ Success message displayed
✓ Password hashed with Werkzeug scrypt (not plaintext in database)


1.2 LOGIN TEST
---------------
Action:
- Navigate to http://localhost:5000/login
- Fill login form:
  * Email: "test@compassiq.com"
  * Password: "Password@123"
- Click "Login" button

Expected Result:
- Session created with user_id, role, email
- Redirected to /customer/dashboard
- Dashboard displays customer name: "Test Customer"
- Navigation shows Sign Out button

Database Verification:
```sql
SELECT user_id, role, account_status FROM users WHERE email = 'test@compassiq.com';
```
Expected: role='customer', account_status='APPROVED'

Edge Case Check:

  * Error message: "Invalid email or password"
  * No session created
  * Remains on login page

- Banned account:
  * Set account_status='BANNED' in database
  * Attempt login

Verification Criteria:
✓ Valid credentials create session
✓ Redirect to role-specific dashboard (customer → /customer/dashboard)
✓ Session stores user_id, role, email
✓ Invalid credentials show error without session creation
✓ Banned accounts blocked from login


Expected: predicted_category='Technical', predicted_priority='High', status='Submitted'

Verification Criteria:
✓ Ticket form accepts valid input

✓ AI Category prediction displayed (Technical)

2.2 AI INFERENCE TEST
---------------------
Action:
- Observe AI predictions displayed on ticket creation confirmation
- Verify TF-IDF vectorization occurred
- Verify Logistic Regression classification executed

Expected Result:
- Category prediction: "Technical" (due to keywords: "error", "502", "API")
- Priority prediction: "High" (due to keywords: "error", "affecting workflow")
- Confidence score computed (predict_proba)

Technical Verification (code walkthrough):
- ai_engine.predict_and_retrieve() called
- Text preprocessing: lowercasing, stopword removal, lemmatization
- TF-IDF vectorization using loaded tfidf_vectorizer.joblib
- Category prediction using category_model.joblib
- Priority prediction using priority_model.joblib
- Confidence scores computed via predict_proba()

Edge Case Check:
- If ML models unavailable:
  * Fallback to rule-based heuristic
  * Keywords: 'error', 'crash', 'bug' → Technical
  * Keywords: 'charge', 'refund' → Billing
  * Default: General Inquiry, Medium priority

- Low confidence prediction (<45%):
  * Manual review indicator displayed
  * System still routes to predicted department

Verification Criteria:
✓ TF-IDF vectorization converts text to numerical features
✓ Logistic Regression classification predicts category and priority
✓ Confidence scores computed for each prediction
✓ Low confidence triggers manual review indicator
✓ Safe fallback mechanism activates if models unavailable
✓ Predictions explainable via feature importance (TF-IDF weights)
