PROJECT NAME & OBJECTIVE
-------------------------
CompassIQ is an AI-powered customer support ticket management system designed
for academic demonstration. The system demonstrates:

1. Role-Based Access Control (RBAC) with three user roles (Customer, Agent, Admin)
2. AI-powered ticket classification using TF-IDF + Logistic Regression
3. SQLite relational database with proper foreign key relationships
4. Full-stack web application using Flask with clean RESTful architecture
5. Customer satisfaction feedback loop with CSAT ratings

Objective: Provide a defendable, line-by-line explainable codebase suitable
for MCA internal viva evaluation while demonstrating core AI/ML concepts.

ACTIVE DATABASE SCHEMA
----------------------
The system uses SQLite with three active tables and one idle table:

1. USERS TABLE
   - user_id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - full_name (TEXT NOT NULL)
   - email (TEXT UNIQUE NOT NULL)
   - password_hash (TEXT NOT NULL) - Werkzeug PBKDF2
   - role (TEXT NOT NULL) - 'customer', 'agent', 'admin'
   - department (TEXT) - Agent's assigned department
   - bill_no_product_id (TEXT) - Customer's product reference
   - account_status (TEXT) - 'APPROVED', 'BANNED' (auto-approved for demo)
   - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

2. TICKETS TABLE
   - ticket_id (TEXT PRIMARY KEY) - Format: TKT-XXXXXX
   - customer_id (INTEGER FOREIGN KEY → users.user_id)
   - subject (TEXT NOT NULL)
   - description (TEXT NOT NULL)
   - predicted_category (TEXT) - AI prediction
   - predicted_priority (TEXT) - AI prediction
   - assigned_department (TEXT) - Mapped from category
   - assigned_agent_id (INTEGER FOREIGN KEY → users.user_id)
   - status (TEXT) - 'Submitted', 'Under Review', 'In Progress', 'Resolved', 'Closed'
   - resolution_notes (TEXT)
   - satisfaction_score (INTEGER) - 1-5 star rating
   - customer_feedback (TEXT)
   - resolved_at (TIMESTAMP)
   - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

3. TICKET_REPLIES TABLE
   - reply_id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - ticket_id (TEXT FOREIGN KEY → tickets.ticket_id)
   - sender_id (INTEGER FOREIGN KEY → users.user_id)
   - message (TEXT NOT NULL)
   - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

4. TICKET_SIMILAR_MATCHES TABLE (IDLE - Kept for schema compatibility)
   - match_id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - ticket_id (TEXT FOREIGN KEY → tickets.ticket_id)
   - similar_ticket_ref_id (TEXT)
   - similarity_score (REAL)
   - similar_subject (TEXT)
   - similar_description (TEXT)
   - historical_resolution_hours (REAL)
   - NOTE: This table is not used in the simplified version. Historical
     corpus similarity search was removed for startup optimization (<2s boot).


ACTIVE ML PIPELINE
------------------
The ML system uses a lightweight, explainable pipeline suitable for viva defense:

1. MODEL ARTIFACTS (3 files in models/ directory)
   - tfidf_vectorizer.joblib: TfidfVectorizer (max_features=5000, ngram_range=(1,2))
   - category_model.joblib: LogisticRegression classifier for 4 categories
   - priority_model.joblib: LogisticRegression classifier for 4 priorities

2. CLASSIFICATION ALGORITHM
   - TF-IDF (Term Frequency-Inverse Document Frequency)
     - Converts text to numerical feature vectors
     - Reflects word importance in the document corpus
   - Logistic Regression
     - Multi-class classification with probability estimation
     - Uses predict_proba() for confidence scoring
     - Low confidence flag (<45%) triggers manual review indicator

3. PREDICTION CATEGORIES
   - Category: Technical, Billing, Account, General Inquiry
   - Priority: Critical, High, Medium, Low
   - Department Mapping: 1:1 (Technical → Technical, etc.)

4. SAFE FALLBACK MECHANISM
   - If ML models are unavailable, rule-based heuristic uses keyword matching
   - Keywords: 'error', 'crash', 'bug' → Technical; 'charge', 'refund' → Billing
   - Ensures system remains functional during demo even without trained models

5 EVALUATION CORE FLOWS
------------------------
The viva evaluation covers 5 core workflows:

FLOW 1: AUTHENTICATION (Auto-Approved Registration, Login, Logout)
- /register: Creates user with APPROVED status (no admin approval needed)
- /login: Validates credentials, creates session, redirects to role dashboard
- /logout: Clears session, redirects to login

FLOW 2: CUSTOMER PORTAL (Create Tickets, View History, Submit Feedback)
- /customer/dashboard: Shows all customer tickets
- /customer/tickets/create: Creates ticket with AI predictions
- /customer/tickets/<id>/reply: Customer submits reply
- /customer/tickets/<id>/feedback: CSAT 1-5 star rating

FLOW 3: AI INFERENCE (Called during ticket creation)
- ai_engine.predict_and_retrieve():
  1. Text preprocessing (lowercasing, stopword removal, lemmatization)
  2. TF-IDF vectorization
  3. Category prediction (Logistic Regression)
  4. Priority prediction (Logistic Regression)
  5. Confidence scoring using predict_proba()
  6. Safe fallback to rule-based heuristic

FLOW 4: AGENT PORTAL (Department Queues, Ticket Resolution, Replies)
- /agent/dashboard: Shows department-specific ticket queue
- /agent/tickets/<id>/details: Fetches ticket with conversation history
- /agent/tickets/<id>/reply: Agent updates status, adds reply, resolution notes

FLOW 5: ADMIN PORTAL (System Metrics, Category Distribution Analytics)
- /admin/dashboard: Shows 3 metric cards + 1 category distribution chart
- Metrics: Total Tickets, Open Tickets, Resolved Tickets
- Chart: Category distribution using Chart.js

STARTUP OPTIMIZATION
--------------------
The system is optimized for <2 second startup time:

1. Database Schema Check
   - Checks if USERS table exists
   - Instant no-op if schema already initialized
   - Runs schema.sql only on first startup

2. ML Model Verification
   - Checks for 3 model artifacts (removed historical corpus)
   - Runs train_model.py only if models missing
   - Loads models once in single process

3. Flask Configuration
   - debug=True (for error reporting)
   - use_reloader=False (prevents watchdog false triggers from OneDrive)
   - Manual restart required after code changes


CSRF PROTECTION
---------------
All POST forms include CSRF protection using Flask-WTF:

- Configuration: WTF_CSRF_TIME_LIMIT = None (no timeout for demo)
- Hidden field: <input type="hidden" name="csrf_token" value="{{ csrf_token() }}"/>
- Applied to: login.html, register.html, ticket forms
- Token validation handled automatically by Flask-WTF


SECURITY FEATURES
-----------------
1. Password Hashing: Werkzeug PBKDF2 with salt
2. CSRF Protection: Flask-WTF tokens on all POST forms
3. Session Management: Secure Flask sessions with SECRET_KEY
4. SQL Injection Prevention: Parameterized queries (sqlite3 ? placeholders)
5. Role-Based Access Control: Decorators (@customer_required, @agent_required, @admin_required)
6. Account Status Check: BANNED users blocked from login

VIVA DEFENSE POINTS
-------------------
1. Why TF-IDF?
   - Explainable, interpretable feature extraction
   - Standard NLP technique for text classification
   - Computes word importance in document corpus

2. Why Logistic Regression?
   - Linear classifier with probability estimation
   - Provides confidence scores for low-confidence flagging
   - Fast inference suitable for real-time classification

3. Why SQLite?
   - Zero-configuration, file-based database
   - Suitable for demo scale and academic projects
   - Standard SQL with proper foreign key relationships

4. Why Auto-Approval?
   - Streamlined demo flow for viva evaluation
   - Eliminates waiting for admin approval
   - Focuses on AI/ML features rather than enterprise workflows

5. Why Simplified 3-Link Navigation?
   - Reduces UI complexity for viva presentation
   - Focuses evaluation on core flows
   - Eliminates confusion during demo
