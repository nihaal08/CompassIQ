1. PROJECT OVERVIEW & EXECUTIVE SUMMARY
================================================================================

Project Name: CompassIQ — AI-Powered Ticket Management System

Core Objective: 
Automating customer support ticket triage, classification, priority prediction, 
department routing, and historical resolution retrieval using NLP and Machine 
Learning for consumer electronics customer support.

Problem Statement & Motivation:
Manual ticket routing delays response times and causes misrouting. CompassIQ 
automates categorization, surfaces Top-3 historical ticket solutions, and 
optimizes support staff workflows through intelligent AI-driven routing and 
recommendation systems.

Key Innovation:
- Real-time NLP-based ticket classification using TF-IDF and Logistic Regression
- Top-3 historical similar ticket retrieval using cosine similarity
- Dynamic department routing based on predicted categories
- Role-based access control with security gatekeeping
- Interactive analytics and fraud detection capabilities
- CSRF protection for secure form submissions
- Asynchronous modal interactions for improved UX

================================================================================
2. SYSTEM ARCHITECTURE & COMPLETE WORKFLOW
================================================================================

End-to-End Workflow:

1. Registration & Security Gatekeeping
   - Customer signs up with Bill No/Product ID for verification
   - Account enters PENDING state awaiting Admin approval
   - Login restricted to APPROVED accounts only
   - Admin can assign departments to agents during approval

2. Ticket Submission
   - Customer submits complaint with Subject and Description
   - System generates unique Ticket ID (TKT-XXXXXX format)
   - CSRF token validation for secure form submission

3. AI Preprocessing & Inference
   - NLP pipeline cleans text (lowercase, punctuation removal, lemmatization)
   - TF-IDF vectorization extracts features from processed text
   - Balanced Logistic Regression predicts Issue Category (5 classes)
   - Priority prediction using balanced ML model (4 levels)
   - Fraud detection via keyword matching + ML classification
   - Safe fallback mechanisms for model failures or edge cases

4. Top-3 Historical Match Retrieval
   - Cosine similarity identifies nearest historical resolutions
   - Returns top 3 matches with percentage similarity scores
   - Includes historical resolution time estimates

5. Dynamic Ticket Routing
   - Routes to appropriate department: Technical, Billing, Account, General Inquiry
   - Fraud cases automatically routed to Admin_Fraud queue
   - Department agents see only relevant tickets

6. Agent Workspace & Resolution
   - Agent inspects AI recommendations and similar historical tickets
   - Can reference historical solutions in responses
   - Replies to customer and updates status (asynchronous modal submission)
   - Tracks resolution time and quality

7. Customer Resolution & Feedback
   - Customer views real-time communication thread in modal
   - Visual 5-stage progress tracker shows ticket status
   - Asynchronous reply submission without page reload
   - Upon resolution, customer submits 1-5 star CSAT rating
   - Optional qualitative feedback collection

8. Admin Intelligence
   - Real-time telemetry dashboard with KPI metrics (including critical ticket count)
   - User approval queue with department assignment for agents
   - Fraud escalation desk for security incidents
   - Interactive Chart.js analytics for department performance
   - CSRF-protected admin actions

ai_engine.py (AI Inference & Similarity Engine)
-----------------------------------------------
Purpose: Loads pre-trained ML models and performs real-time ticket 
classification, priority prediction, and historical similarity matching.

Key Functions:
- load_ai_engine(): Loads all serialized models on startup with error handling
- clean_text(): NLP preprocessing (lowercase, punctuation, lemmatization)
- predict_and_retrieve(): Main inference function for ticket processing
- _heuristic_fallback(): Rule-based fallback when ML models unavailable
- cosine_similarity calculation for historical matches

Global Variables:
- vectorizer: TF-IDF feature extractor
- category_model: Logistic Regression for category classification
- priority_model: Logistic Regression for priority prediction
- historical_corpus: Pre-computed TF-IDF matrix of historical tickets
- FRAUD_INDICATORS: Set of high-risk keywords for fraud detection

ML Pipeline:
1. Text preprocessing and cleaning with input validation
2. TF-IDF feature extraction
3. Category prediction (5 classes: Technical, Billing, Account, General Inquiry, Fraud)
4. Priority prediction (4 levels: Low, Medium, High, Critical)
5. Fraud keyword matching for security escalation
6. Top-3 historical similar ticket retrieval via cosine similarity
7. Safe fallback mechanisms for model failures or edge cases

Output Format:
Returns dictionary with:
- predicted_category: String classification
- predicted_priority: String priority level
- category_confidence: Prediction confidence percentage (e.g., "89.4%")
- priority_confidence: Priority confidence percentage
- low_confidence: Boolean flag for manual review (< 45% confidence)
- fraud_flagged: Boolean indicating security concern
- similar_tickets: List of top 3 historical matches with similarity scores

Enhanced Features:
- Prediction confidence scoring using predict_proba()
- Low confidence flag for human intervention
- Hybrid fraud arbitration (rule-based + ML)
- Fast sparse matrix similarity retrieval (< 2ms)
- Comprehensive error handling and safe fallbacks
- Input validation for empty or malformed text

Safe Fallback Mechanisms:
- Empty input validation before processing
- Try-catch blocks around ML model predictions
- Default fallback values: General Inquiry, Medium priority, Technical department
- Graceful degradation when model files are missing
- Comprehensive error logging for debugging

train_model.py (ML Model Training Pipeline)
-------------------------------------------
Purpose: Trains machine learning models from customer support data, handles 
class imbalance, prevents data leakage, and exports production-ready artifacts.

Key Functions:
- clean_text(): Text preprocessing for training data
- train_and_export(): Main training pipeline with data leakage prevention
- generate_eda_visualizations(): Exploratory data analysis visualizations

ML Components:
- TF-IDF Vectorizer: Feature extraction from text (max_features=5000, ngram_range=(1,2))
- Logistic Regression: Classification for both category and priority with probability estimation
- SMOTE: Synthetic minority oversampling for class balance (sampling_strategy='auto', random_state=42)
- Train-test split: 80-20 stratified split BEFORE vectorization (data leakage prevention)

Data Leakage Prevention:
- 80/20 train-test split performed BEFORE fitting TF-IDF vectorizer
- Vectorizer fitted strictly on training data (train_df['cleaned_text'])
- SMOTE applied strictly to training TF-IDF matrix (X_train_tfidf)
- Historical corpus built strictly from training partition
- Test partition remains completely unseen during training

Evaluation Metrics:
- Macro F1-score: Evaluates performance across all classes equally
- Weighted F1-score: Accounts for class distribution imbalance
- Per-class Precision and Recall for minority classes (Fraud, Critical)
- Classification reports with detailed metrics
- Class distribution analysis before and after SMOTE

5. DATABASE SCHEMA & RELATIONSHIPS
================================================================================

Table: users
-----------
- user_id (INTEGER PRIMARY KEY AUTOINCREMENT)
- full_name (TEXT NOT NULL)
- email (TEXT UNIQUE NOT NULL)
- password_hash (TEXT NOT NULL)
- role (TEXT NOT NULL DEFAULT 'customer') CHECK(role IN ('customer', 'agent', 'admin'))
- department (TEXT DEFAULT 'None') CHECK(department IN ('Technical', 'Billing', 'Account', 'General Inquiry', 'None'))
- bill_no_product_id (TEXT)
- account_status (TEXT DEFAULT 'PENDING') CHECK(account_status IN ('PENDING', 'APPROVED', 'REJECTED', 'BANNED'))
- created_at (DATETIME DEFAULT CURRENT_TIMESTAMP)

Table: tickets
-----------
- ticket_id (TEXT PRIMARY KEY)
- customer_id (INTEGER NOT NULL) -> REFERENCES users(user_id) ON DELETE CASCADE
- subject (TEXT NOT NULL)
- description (TEXT NOT NULL)
- predicted_category (TEXT NOT NULL) CHECK(predicted_category IN ('Technical', 'Billing', 'Account', 'General Inquiry', 'Fraud'))
- predicted_priority (TEXT NOT NULL) CHECK(predicted_priority IN ('Low', 'Medium', 'High', 'Critical'))
- assigned_department (TEXT NOT NULL) CHECK(assigned_department IN ('Technical', 'Billing', 'Account', 'General Inquiry', 'Admin_Fraud'))
- status (TEXT DEFAULT 'Submitted') CHECK(status IN ('Submitted', 'Under Review', 'In Progress', 'Resolved', 'Closed'))
- assigned_agent_id (INTEGER) -> REFERENCES users(user_id) ON DELETE SET NULL
- resolution_notes (TEXT)
- satisfaction_score (INTEGER CHECK(satisfaction_score BETWEEN 1 AND 5))
- customer_feedback (TEXT)
- created_at (DATETIME DEFAULT CURRENT_TIMESTAMP)
- resolved_at (DATETIME)

Table: ticket_similar_matches
----------------------------
- match_id (INTEGER PRIMARY KEY AUTOINCREMENT)
- ticket_id (TEXT NOT NULL) -> REFERENCES tickets(ticket_id) ON DELETE CASCADE
- similar_ticket_ref_id (TEXT NOT NULL)
- similarity_score (REAL NOT NULL)
- similar_subject (TEXT NOT NULL)
- similar_description (TEXT NOT NULL)
- historical_resolution_hours (INTEGER)
- created_at (DATETIME DEFAULT CURRENT_TIMESTAMP)

Table: ticket_replies
--------------------
- reply_id (INTEGER PRIMARY KEY AUTOINCREMENT)
- ticket_id (TEXT NOT NULL) -> REFERENCES tickets(ticket_id) ON DELETE CASCADE
- sender_id (INTEGER NOT NULL) -> REFERENCES users(user_id) ON DELETE CASCADE
- message (TEXT NOT NULL)
- created_at (DATETIME DEFAULT CURRENT_TIMESTAMP)

Foreign Key Relationships:
- tickets.customer_id -> users.user_id (CASCADE DELETE)
- tickets.assigned_agent_id -> users.user_id (SET NULL)
- ticket_similar_matches.ticket_id -> tickets.ticket_id (CASCADE DELETE)
- ticket_replies.ticket_id -> tickets.ticket_id (CASCADE DELETE)
- ticket_replies.sender_id -> users.user_id (CASCADE DELETE)

Valid Status Values:
- Account Status: PENDING, APPROVED, REJECTED, BANNED
- Ticket Status: Submitted, Under Review, In Progress, Resolved, Closed
- Categories: Technical, Billing, Account, General Inquiry, Fraud
- Priorities: Low, Medium, High, Critical
- Departments: Technical, Billing, Account, General Inquiry, Admin_Fraud

8. AI/ML PIPELINE DETAILS
================================================================================

Model Algorithms:
- Category Classification: Multinomial Logistic Regression with SMOTE
- Priority Prediction: Multinomial Logistic Regression with SMOTE
- Feature Extraction: TF-IDF Vectorizer (unigrams + bigrams)
- Similarity Retrieval: Sparse Cosine Similarity (linear_kernel optimization)

Category Labels:
- Technical: Hardware/software issues, errors, crashes
- Billing: Charges, refunds, invoices, payment issues
- Account: Login, password, 2FA, profile management
- General Inquiry: Product information, warranty, API documentation
- Fraud: Security incidents, unauthorized access, phishing

Priority Thresholds:
- Critical: Immediate security threat, system-wide outage
- High: Major functionality loss, urgent customer impact
- Medium: Standard support request, normal operations
- Low: Informational requests, non-urgent issues

Confidence Scoring:
- Category confidence: Probability percentage from predict_proba()
- Priority confidence: Probability percentage from predict_proba()
- Low confidence flag: Triggered when confidence < 45%
- Manual review: Recommended for low confidence predictions

Fallback Mechanisms:
- Empty input: Returns General Inquiry/Medium priority
- Model failure: Defaults to rule-based heuristic classification
- Missing models: Uses keyword-based category detection
- Error logging: Comprehensive error messages for debugging

Fraud Detection:
- Hybrid approach: Rule-based keyword matching + ML classification
- Fraud indicators: 19 high-risk keywords (fraud, scam, phishing, hacked, etc.)
- Automatic escalation: Routes to Admin_Fraud department
- Priority override: Fraud cases always set to Critical priority

10. SETUP & EXECUTION
================================================================================

Installation Steps:

1. Navigate to project directory:
   cd CompassIQ-AI

2. Create virtual environment (recommended):
   python -m venv venv
   
   Activate virtual environment:
   - Windows: venv\Scripts\activate
   - macOS/Linux: source venv/bin/activate

3. Install dependencies:
   pip install -r requirements.txt

4. Train ML models:
   python train_model.py

5. Start application:
   python app.py

6. Access at: http://127.0.0.1:5000

Troubleshooting:
- If models fail to load, run train_model.py
- If database errors occur, delete database/storage/compassiq.db and restart
- For CSRF errors, ensure Flask-WTF is properly installed
- Check Python version compatibility (3.11+ recommended)
